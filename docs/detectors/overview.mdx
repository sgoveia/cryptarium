# Detectors overview

Detectors extract cryptographic evidence. They do not classify quantum exposure — that is the classifier's job after correlation.

| Detector | Input | Output signal |
|---|---|---|
| Source | Parsed source via rule packs (Go, Python, JS/TS, Java, C/C++) | Call sites, primitives, parameters |
| Dependencies | `go.mod` + known-library catalog | Crypto libraries present (medium confidence) |
| Certificates | PEM/DER/PKCS#12 (`.pem`, `.crt`, `.cer`, `.der`, `.key`, `.p12`, `.pfx`) | Algorithms, sizes, curves, validity (metadata only) |
| Configuration | nginx TLS suites, SSH algorithms, JWT `alg` | Configured suites and algorithms |

## Design constraints

- Prefer AST / structured parsing over regex; regex is an explicit fallback with lowered confidence.
- Never emit key material — metadata only, redacted snippets.
- Unparseable files must produce warnings.
